# 持久化与并发隔离实验

**可丢弃的技术原型。** 使用 Python 标准库 SQLite 和预先归一化的合成微信/银行记录，验证同订单关联在进程重试、两进程同时提交、提交中进程退出和批次部分入账时是否重复计数。没有真实账单或 DSH 插件调用。

在仓库根目录运行：

```powershell
python .\experiments\finance-sqlite-probe\verify.py
```

脚本逐场景打印结果与账本状态；每次运行在根目录被忽略的 `.runtime/finance-sqlite-probe/` 中新建独立临时数据库。它不修改 `config/plugins.json`。数据库仅供实验，不作为正式数据模型或可靠备份实现。

验证重点：同一请求返回原结果、新批次重导跳过并提醒；两个进程竞争同一订单，最终只保留一次消费与账户扣款；进程在写入效果后、提交前退出，SQLite 回滚整个单元，重试可完成；一个订单组有缺失日期时待核对，其他独立订单先提交。

边界：输入已归一化，不验证个人微信/银行文件字段；只处理消费与银行扣款，不处理退款、充值、借贷、后续依赖或旧账目迁移。批次按独立订单组提交，完整批次并非一个事务。两进程试验不等于已验证任意并发量、磁盘故障或生产迁移。
