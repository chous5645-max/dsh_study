# 跨来源匹配隔离实验

**可丢弃的逻辑原型。** 问题：稳定共同订单号、事实相容时自动关联，能否与同源重复跳过、批次部分入账和金额不重复约束共存？本实验只处理预先归一化的合成微信/银行记录，状态仅在内存中。它不属于 `config/plugins.json` 中启用的插件，也不读取真实账单。

在仓库根目录用一条命令运行：

```powershell
node .\experiments\finance-cross-source\verify.mjs
```

脚本逐步打印操作结果和完整相关状态，并检查：共同订单号自动关联、同源重导提醒、同一请求重试、两种导入顺序、同号不同作用域、同额不同订单、冲突与金额/日期不清的部分批次、多目标歧义、两个既有账目的合并，以及过期预览的重评估。它验证的是这些合成状态转移的可行性，不验证真实微信/银行格式、订单号字段映射、跨日期结算窗口、数据库事务、跨进程并发、依赖退款/报销的合并或 DSH 插件接入。技术依据见[来源身份与匹配方案](../../finance/docs/technical/source-identity-and-matching.md)。

2026-09-24 本机 Node.js 24.19.0 运行断言通过。实现时发现同订单的一条来源缺少日期会让另一条来源错误地单独入账，已改为同组待核对；独立订单仍可先入账。结论与范围见[技术验证记录](../../finance/docs/technical/source-identity-and-matching.md#7-2026-09-24-合成隔离验证结果)。
