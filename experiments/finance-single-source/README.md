# 单来源导入隔离实验

本目录验证 V2 中最小的“预览 → 提交 → 查询”账务链路，使用[合成 CSV](fixtures/january.csv)和[重叠导出样例](fixtures/overlap.csv)。它不属于 `config/plugins.json` 中启用的插件，也不读取真实账单。

从仓库根目录运行：

```powershell
node .\experiments\finance-single-source\verify.mjs
```

验证脚本在被忽略的 `.runtime/` 中建立独立状态，检查预览不入账、同文件重导、重叠导出、不同交易标识的同额记录、来源行追溯、分类汇总、重启后读取、相同请求重试、幂等标识冲突、过期预览和无效输入。2026-09-23 的一次本机运行通过；这只覆盖[V0 样例 01、02](../../finance/docs/planning/v0-acceptance-cases.md)及 04 中“不同标识不可按金额合并”的部分规则，不表示整组 V0 业务口径已经验收。

当前只接受固定表头的合成 CSV、已完成的支出，以及样例中已明确的真实账户。它不声称兼容微信或支付宝的实际导出文件；不处理收入、退款、转账、跨来源匹配或真实账户期初余额。持久化使用本地 JSON 快照，版本冲突检查保守地以全账本修订号为准；跨进程并发、崩溃中的文件恢复和正式 DSH 插件接入均未验证。稳定规则与实现需按后续验证结果再迁入 `plugins/`。
