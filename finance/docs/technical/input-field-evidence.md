# 个人账单与银行流水的字段证据

日期：2026-09-24。状态：**真实字段映射待验证**。本页只记录可证明的输入事实与缺口，不把商户账单文档当作个人微信账单或银行截图的格式说明。

## 当前证据

| 来源 | 已能确认 | 尚不能确认 |
| --- | --- | --- |
| 本仓库样例 | 目前跟踪的账单文件只有 `experiments/finance-single-source/fixtures/` 中的固定合成 CSV；跨来源实验也使用预先归一化的合成对象。 | 个人微信 CSV/Excel 的实际列名、前置说明、状态和订单号语义；银行截图实际显示哪些编号。 |
| [财付通隐私政策](https://www.tenpay.com/v3/helpcenter/low/privacy.shtml) | 个人微信支付交易记录可以从账单入口下载。 | 该政策没有给出个人导出文件的字段表，不能据此证明它与银行流水共享订单号。 |
| [微信支付商户交易账单文档](https://pay.wechatpay.cn/doc/v3/merchant/4013071246) | 商户交易账单区分微信订单号、商户订单号等字段。 | 文档适用于商户账单，不能作为个人账单的字段契约，也不能说明某家银行截图会展示其中任何一个编号。 |

因此，[D19 的自动关联条件](../decisions.md)仍是**有条件的业务规则**：只有两端实际提供同一稳定订单号、字段语义属于同一编号体系且其他事实不冲突时才能自动应用。现有合成实验只验证这条规则在假定字段已正确归一化之后的状态转移，未证明真实输入满足前提。

## 收到样例后的字段核对

每个来源单独记录格式与版本、获取入口、文件编码/工作表或截图位置、表头及明细边界、交易标识字段、订单号字段的原始名称与含义、金额及方向、支付渠道与真实资金账户、交易/入账时间、交易状态、退款及撤销字段。订单号按文本处理，保留前导零与原始值。

对**同一笔**微信与银行记录，再核对：

1. 两边是否真的出现相同编号；若不同，是否有官方或来源内证据说明它们属于同一编号体系。
2. 编号是否稳定且在同一作用域内唯一；退款、撤销、分次扣款会不会复用它。
3. 银行记录是否代表微信银行卡代扣，还是微信零钱充值、还款或另一个资金事件。
4. 金额、币种、方向、状态及时间差是否能由来源字段解释；无法解释的差异进入核对。
5. 同一交易重导、不同交易同额、相同编号文本但字段语义不同等反例是否安全。

结论按来源样式版本记录为“已验证可自动关联 / 只能提出候选 / 字段不足无法匹配”，并保留对应的合成化复现样例。未经验证的来源样式不默认继承其他银行或其他导出版本的映射。

2026-09-24 用户表示暂时没有脱敏样例。本仓库不收录真实原始账单；未来样例可临时放在被忽略的根 `.runtime/`，仅把脱敏后的字段结论和合成复现输入写回版本控制。脱敏时可一致替换两端的订单号以保留相等关系，并移除姓名与完整账号。
