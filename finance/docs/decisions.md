## 提案，尚未冻结

- 核心业务契约见 [core-interface.md](technical/core-interface.md)：UI/Agent 共用类型化业务操作；提案与应用分离；核心校验版本、幂等及确认依据；方法名称和传输方式尚未冻结。

- 统一草稿与提交规则见 [drafts-and-posting.md](technical/drafts-and-posting.md)：字段依据分开，核心决定阻断或允许；缺分类可入账，账户或用途不完整仅确认有依据的影响。两种待补正式账目已确认；批次部分提交及自动执行条件尚待确认。

- 分类、标签、事项细化见 [categories-tags-and-events.md](requirements/categories-tags-and-events.md)：主分类表达性质，多标签交叉筛选，事项归组具体活动；金额拆分与业务结算独立于标签。细节待验证。

- 押金、预付、储值和投资资产提案见 [assets-and-prepayments.md](requirements/assets-and-prepayments.md)；区分真实付款、消费成本、商户额度及资产估值。储值的充值记消费/使用记消费需明确规则，不能重复记消费和资产。

- 预算、周期计划与预测提案见 [budgets-and-planning.md](requirements/budgets-and-planning.md)：预算与现金付款分开，计划不自动入账，预测只计未执行部分，并明确收款场景和覆盖范围。

- 报表建议：实际流水按发生日，消费按原消费归属日回看；退款/报销承担份额调整消费，报销到账仅结算应收。认知截止时间与历史余额分开，详见 [reports-and-analysis.md](requirements/reports-and-analysis.md)；待确认。

- 核心拥有导入、统计计算与报表数据，UI 拥有交互、图表与排版。
- 本地运行与 SQLite 为技术候选；用户数量和版本范围待整体讨论后决定。多币种已明确暂缓。
- 账本独立于会话，保存来源记录与变更记录。
- 核心与 UI 同仓库，固定 DSH 版本，逐阶段验证。
- 父子拆分、事项归组与有类型的多对多关联为数据模型候选；具体结构尚未冻结。

- 具体对象模型与跨入口合并见 [concrete-object-model.md](technical/concrete-object-model.md)：区分来源、业务金额、账户变动、分配、关系及操作；“先自然语言记账，后导入银行流水”只补缺失影响或证据。具体对象边界与自动匹配条件仍为提案；两种待补正式账目已确认。

- 账本跨会话共享范围，以及账单分析结果的历史可复现程度。
